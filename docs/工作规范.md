## 💻 代码规范

### Python后端规范

#### 1. 代码风格
- 遵循 **PEP 8** 规范
- 使用 **Black** 进行代码格式化
- 使用 **Ruff** 进行代码检查
- 最大行长度：88字符

#### 2. 命名规范
```python
# 文件名：小写+下划线
docx_parser.py

# 类名：大驼峰
class DocumentParser:
    pass

# 函数名：小写+下划线
def parse_document():
    pass

# 常量：大写+下划线
MAX_FILE_SIZE = 10485760

# 私有方法：前缀下划线
def _internal_method():
    pass
```

#### 3. 类型注解
```python
# 必须使用类型注解
def process_text(text: str, mode: str) -> list[str]:
    return []

# 复杂类型使用typing
from typing import Optional, List, Dict

def get_document(doc_id: str) -> Optional[Dict[str, any]]:
    return None
```

#### 4. 文档字符串
```python
def upload_document(file: UploadFile) -> dict:
    """
    上传并解析Word文档
    
    Args:
        file: 上传的文件对象
        
    Returns:
        包含文档信息的字典
        
    Raises:
        ValueError: 文件格式不支持
    """
    pass
```

### TypeScript前端规范

#### 1. 代码风格
- 遵循 **ESLint** 规则
- 使用 **Prettier** 格式化
- 使用严格模式 `"strict": true`

#### 2. 命名规范
```typescript
// 文件名：大驼峰（组件）或小驼峰（工具）
FileUploader.tsx
api.ts

// 组件名：大驼峰
export default function FileUploader() {}

// 函数名：小驼峰
function handleUpload() {}

// 常量：大写+下划线
const MAX_FILE_SIZE = 10485760

// 接口：大驼峰+I前缀（可选）
interface Document {
  id: string
}
```

#### 3. 类型定义
```typescript
// 优先使用interface而非type
interface User {
  id: string
  name: string
}

// 复杂类型使用type
type Status = 'pending' | 'success' | 'error'

// 导出所有类型
export type { User, Status }
```

#### 4. React组件规范
```typescript
// 使用函数组件
export default function MyComponent({ prop1, prop2 }: Props) {
  // Hooks在顶部
  const [state, setState] = useState()
  
  // 事件处理函数
  const handleClick = () => {}
  
  // 渲染
  return <div>...</div>
}

// Props类型定义
interface Props {
  prop1: string
  prop2?: number  // 可选属性
}
```

## 🔧 Git提交规范

### Commit Message格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### Type类型

| Type | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(api): 添加文件上传接口` |
| `fix` | Bug修复 | `fix(parser): 修复XML解析错误` |
| `docs` | 文档更新 | `docs(readme): 更新安装说明` |
| `style` | 代码格式 | `style(backend): 格式化代码` |
| `refactor` | 重构 | `refactor(api): 重构上传逻辑` |
| `test` | 测试 | `test(parser): 添加单元测试` |
| `chore` | 构建/工具 | `chore(deps): 更新依赖版本` |
| `perf` | 性能优化 | `perf(api): 优化查询性能` |

### 示例

```bash
# 好的提交
git commit -m "feat(upload): 实现文件上传和验证功能"
git commit -m "fix(parser): 修复中文段落解析问题"
git commit -m "docs(api): 更新API文档，添加新端点说明"

# 不好的提交
git commit -m "update"
git commit -m "fix bug"
git commit -m "修改了一些东西"
```

### 分支管理

```
main          # 主分支，稳定版本
├── dev       # 开发分支
├── feature/* # 功能分支
├── fix/*     # 修复分支
└── release/* # 发布分支
```

### 工作流程

```bash
# 1. 创建功能分支
git checkout -b feature/upload-api

# 2. 开发并提交
git add .
git commit -m "feat(upload): 实现文件上传功能"

# 3. 推送到远程
git push origin feature/upload-api

# 4. 创建Pull Request
# 5. 代码审查
# 6. 合并到dev分支
```

## 📝 文档更新规范

### 必须更新的时机

#### 1. 每次开发会话结束时

**必须更新**：
- ✅ `docs/开发日志.md`
- ✅ `docs/下一次对话提示词.md`

**更新内容**：
```markdown
## 2026-02-03

### 完成内容
- ✅ 实现了XXX功能
- ✅ 修复了XXX问题

### 下一步计划
- [ ] 待完成XXX
```

#### 2. 新增或修改API时

**必须更新**：
- ✅ `docs/API文档.md`

**更新内容**：
- 端点路径和方法
- 请求参数
- 响应格式
- 状态标记（已实现/待实现）

#### 3. 遇到重要问题时

**必须记录**：
- ✅ 在 `docs/开发日志.md` 中记录

**记录内容**：
- 问题描述
- 错误信息
- 解决方案
- 参考资料

### 文档更新检查清单

每次提交代码前，检查：

- [ ] 开发日志是否更新？
- [ ] API文档是否同步？
- [ ] 下一次对话提示词是否更新？
- [ ] 代码注释是否完整？
- [ ] README是否需要更新？

## 🔄 开发流程

### 标准开发流程

```
1. 查看"下一次对话提示词.md"
   ↓
2. 创建功能分支
   git checkout -b feature/xxx
   ↓
3. 开始编码
   - 编写代码
   - 添加注释
   - 编写测试
   ↓
4. 本地测试
   - 运行单元测试
   - 手动测试功能
   ↓
5. 更新文档
   - 更新开发日志
   - 更新API文档
   - 更新下一次对话提示词
   ↓
6. 提交代码
   git add .
   git commit -m "feat(xxx): 描述"
   ↓
7. 推送到远程
   git push origin feature/xxx
   ↓
8. 创建Pull Request（如需要）
```

### 每日工作流程

#### 开始工作
1. 拉取最新代码：`git pull origin main`
2. 查看开发日志和下一次对话提示词
3. 确认今日任务

#### 结束工作
1. 提交所有代码
2. 更新开发日志
3. 更新下一次对话提示词
4. 推送到远程仓库

## ⚠️ 重要提醒

### 代码质量
- ✅ 代码必须通过Lint检查
- ✅ 核心功能必须有测试
- ✅ 复杂逻辑必须有注释
- ✅ API必须有文档

### 文档同步
- ✅ 代码和文档必须同步更新
- ✅ 不要积累文档更新
- ✅ 每次会话结束必须更新

### Git规范
- ✅ Commit message必须清晰
- ✅ 不要提交.env文件
- ✅ 不要提交node_modules
- ✅ 不要提交临时文件

### 安全规范
- ✅ API Key不能硬编码
- ✅ 敏感信息使用环境变量
- ✅ 用户上传文件必须验证
- ✅ API必须有错误处理
