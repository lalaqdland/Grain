# 测试报告（export 原子性回归修复）

- 日期：2026-02-07
- 分支：`dev`
- 版本：`v3.1.2`
- 目标：修复 `POST /api/v1/export` 在 mixed-id 失败场景下的半应用污染问题

## 1. 问题复现结论（修复前）

复现场景：

1. 上传文档并记录合法段落 ID（如 `para_000000`）。
2. 调用 `POST /api/v1/export`，`modifications` 同时包含：
   - 一个合法 ID
   - 一个非法 ID（如 `para_not_exist`）
3. 接口返回 `400`。
4. 再调用 `GET /api/v1/export/{doc_id}` 导出。

修复前现象：

- 第 4 步导出的文档已包含第 2 步合法 ID 的替换文本，说明失败请求污染了缓存处理器状态。

## 2. 修复策略

- `XMLProcessor.apply_modifications` 改为严格原子语义：
  - 先校验全部段落 ID；
  - 若存在非法 ID，直接返回失败，不执行任何替换；
  - 应用阶段异常时回滚已替换段落（防御性）。
- `POST /api/v1/export` 失败响应固定返回：
  - `detail.applied_ids = []`

## 3. 自动化验证

命令：

```bash
python -m pytest -q
```

结果：

- `12 passed in 0.45s`

新增/更新覆盖点：

- 单测：mixed-id 时 `applied_ids=[]`，并断言段落文本未被修改。
- 集成：mixed-id 导出返回 `400` 后，再次导出仍为原文（无污染）。

## 4. 修复后结论

- ✅ `POST /api/v1/export` 在 mixed-id 场景不再产生半应用。
- ✅ 同 `doc_id` 后续导出不受失败请求影响。
- ✅ 失败响应字段语义与原子行为一致（`applied_ids=[]`）。
