## 📖 各文档说明

### 1. 产品设计文档 (PDD)

**文件名**: `产品设计文档 (PDD)：Grain (守拙) v3.1.0.md`

**用途**: 
- 产品定义和核心功能说明
- 技术架构设计
- 用户流程设计
- 完整的开发路线图

**更新频率**: 
- 重大功能变更时更新
- 版本升级时更新

**负责人**: 产品经理 / 技术负责人

---

### 2. 开发日志

**文件名**: `开发日志.md`

**用途**:
- 记录每日/每周开发进度
- 记录已完成的功能
- 记录遇到的问题和解决方案
- 记录待办事项

**更新频率**: 
- ⚠️ **每次开发会话结束时必须更新**
- 每完成一个功能模块时更新
- 遇到重要问题时记录

**格式要求**:
```markdown
## YYYY-MM-DD

### Sprint X：任务名称 [状态]

**完成内容**：
- ✅ 已完成项1
- ✅ 已完成项2

**遇到的问题**：
- 问题描述
- 解决方案

**下一步计划**：
- [ ] 待完成项1
- [ ] 待完成项2
```

## ⚠️ 文档更新要求

### 必须更新的情况

1. **每次开发会话结束时**:
   - ✅ 更新 `开发日志.md`
   - ✅ 更新 `下一次对话提示词.md`

2. **新增或修改API时**:
   - ✅ 更新 `API文档.md`
   - 标注端点状态（已实现/待实现）

3. **完成重要功能时**:
   - ✅ 更新 `开发日志.md`
   - 记录功能详情和测试结果

4. **遇到重要问题时**:
   - ✅ 在 `开发日志.md` 中记录问题和解决方案

### 文档更新检查清单

每次开发会话结束前，检查以下项目：

- [ ] 开发日志是否记录了本次完成的工作？
- [ ] API文档是否更新了新增/修改的端点？
- [ ] 下一次对话提示词是否更新了当前进度？
- [ ] 是否记录了遇到的问题和解决方案？
- [ ] 待办事项是否更新？

## 📝 文档编写规范

### 1. 使用Markdown格式
- 使用标题层级（#, ##, ###）
- 使用列表（-, *, 1.）
- 使用代码块（```）
- 使用表格

### 2. 使用Emoji增强可读性
- ✅ 已完成
- ⏳ 进行中
- ❌ 失败/错误
- ⚠️ 警告/注意
- 📝 文档
- 🐛 Bug
- ✨ 新功能
- 🔧 配置

### 3. 保持一致性
- 日期格式：YYYY-MM-DD
- 版本格式：vX.Y.Z
- 状态标记：[已完成/进行中/待开始]

### 4. 及时更新
- 不要积累多天的更新
- 每次会话结束立即更新
- 保持文档与代码同步
