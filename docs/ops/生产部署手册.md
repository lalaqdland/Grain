# Grain 生产部署手册

## 1. 当前线上架构

- Grain 业务服务器: `capoo-hk` (`47.83.120.83`)
- 生产入口域名: `https://grain.capootech.com`
- 统一入口网关: 上海 S1（对外接收 `grain.capootech.com`，再反代到香港 S2）
- 香港 S2 复用 `80` 端口作为上游入口（按 `server_name + allow/deny` 仅允许 S1 源 IP）
- 旧根域兼容: `https://capoo.tech`、`https://www.capoo.tech` 在 S2 做 301 到 `https://capootech.com$request_uri`
- 反向代理: Nginx
- HTTPS: Let's Encrypt (Certbot 自动续期)
- 容器:
  - `grain-frontend` -> `127.0.0.1:3001`
  - `grain-backend` -> `127.0.0.1:8001`

## 2. 路由规则

- 对外生产流量:
  - `https://grain.capootech.com/` -> 上海 S1 -> `http://47.83.120.83:80/` -> `http://127.0.0.1:3001`
  - `https://grain.capootech.com/api/v1/*` -> 上海 S1 -> `http://47.83.120.83:80/api/v1/*` -> `http://127.0.0.1:8001/api/v1/*`
  - `https://grain.capootech.com/api/health` -> 上海 S1 -> `http://47.83.120.83:80/api/health` -> `http://127.0.0.1:8001/health`
- 旧域跳转（香港 S2）:
  - `https://capoo.tech/*` -> `https://capootech.com/*`（301）
  - `https://www.capoo.tech/*` -> `https://capootech.com/*`（301）
- 官网静态页说明:
  - 官网发布源已迁移到独立仓库 `CapooTech-OfficialSite`
  - 本仓库不再托管或发布官网静态资源

## 3. 代码发布（标准流程）

### 3.1 本地准备

```bash
git checkout main
git pull origin main
```

### 3.2 同步代码到服务器

```bash
git archive --format=tar -o .deploy-main.tar main
scp .deploy-main.tar capoo-hk:/opt/gain-project/.deploy-main.tar
ssh capoo-hk "cd /opt/gain-project && tar -xf .deploy-main.tar && rm -f .deploy-main.tar"
```

### 3.3 重建并启动生产容器

```bash
ssh capoo-hk "cd /opt/gain-project && docker compose -f docker-compose.prod.yml up -d --build"
```

### 3.4 发布后验证

```bash
# 对外域名验证（经过上海网关）
curl -I https://grain.capootech.com
curl https://grain.capootech.com/api/health
curl https://grain.capootech.com/api/v1/info

# 香港上游端口验证（在上海网关上执行，带 Host 头）
ssh aliyun-shanghai "curl -I -H 'Host: grain.capootech.com' http://47.83.120.83/"
ssh aliyun-shanghai "curl -f -H 'Host: grain.capootech.com' http://47.83.120.83/api/health"
```

### 3.5 官网发布职责（已拆分）

- 官网仓库: `lalaqdland/CapooTech-OfficialSite`
- 官网 workflow: `CapooTech-OfficialSite/.github/workflows/deploy-capootech.yml`
- 官网发布目录（上海机）:
  - `/opt/sites/capootech/releases/<release_id>/`
  - `/opt/sites/capootech/current`
- 本仓库 `Gain-Project` 不再包含 `sites/capootech`，也不再包含官网发布 workflow。

### 3.6 自动发布（GitHub Actions）

- Grain 自动部署 workflow: `.github/workflows/deploy-grain.yml`
  - `dev` 推送 -> 上海（dev 预览）
  - `main` 推送 -> 香港（grain 生产）
- 官网自动发布已迁移到独立仓库 `CapooTech-OfficialSite`。

### 3.7 API 冒烟（建议）

```bash
# 1) 上传
curl -F "file=@test_files/test_document.docx" https://grain.capootech.com/api/v1/upload

# 2) 改写（句子单元）
curl -X POST https://grain.capootech.com/api/v1/rewrite \
  -H "Content-Type: application/json" \
  -d '{"text":"This is a sentence.","mode":"ai_detection","language":"en","unit":"sentence","option_count":2}'

# 3) 导出（需要替换成真实 doc_id 和段落 id）
curl -X POST https://grain.capootech.com/api/v1/export \
  -H "Content-Type: application/json" \
  -d '{"doc_id":"doc_xxx","modifications":{"para_000000":"REPLACED"}}'
```



```bash
ssh capoo-hk "cd /opt/gain-project && docker compose -f docker-compose.prod.yml up -d --force-recreate"
```

```bash

ssh capoo-hk "systemctl reload nginx"
```

## 9. 注意事项

- 生产环境不要使用 `next dev`，必须使用 `next build + next start`。
- 后端生产环境不要使用 `uvicorn --reload`。
- 预览环境与生产环境必须使用独立目录和端口，不要共用。
- `backend/.env` 属于敏感配置，不要覆盖或提交到仓库。
- 发布后建议至少观察 10-15 分钟日志，确认无持续重启和 5xx。
- 官网变更请在 `CapooTech-OfficialSite` 仓库执行，不要在本仓库找 `sites/capootech`。

## 11. 旧根域跳转缓存排查

若浏览器访问 `https://capoo.tech` 未跳转到 `https://capootech.com`，按以下顺序排查：

1. 服务端基线校验（不受浏览器缓存影响）：
```bash
curl -I https://capoo.tech
curl -I https://www.capoo.tech
```
2. 浏览器无缓存验证：隐身窗口 + 强制刷新（Ctrl+F5）。
3. 清理站点数据：删除 `capoo.tech` 的缓存、cookie、HSTS 条目后重试。
4. 若 `curl` 为 `301` 且浏览器表现异常，可判定为客户端缓存问题。
