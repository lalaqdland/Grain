# Grain 生产部署手册

## 1. 当前线上架构

- 服务器: `capoo-hk` (`47.83.120.83`)
- 应用入口: `https://grain.capootech.com`
- 主域入口:
  - `https://capootech.com` -> 站点引导页（静态页）
  - `https://www.capootech.com` -> `https://capootech.com`
- 主域兼容跳转:
  - `https://capootech.com/api/*` -> `https://grain.capootech.com/api/*`
- 反向代理: Nginx
- HTTPS: Let's Encrypt (Certbot 自动续期)
- 容器:
  - `grain-frontend` -> `127.0.0.1:3001`
  - `grain-backend` -> `127.0.0.1:8001`

## 2. 路由规则

- 前端: `https://grain.capootech.com/` -> `http://127.0.0.1:3001`
- API:
  - `https://grain.capootech.com/api/v1/*` -> `http://127.0.0.1:8001/api/v1/*`
  - `https://grain.capootech.com/api/health` -> `http://127.0.0.1:8001/health`
- 主域引导页:
  - `https://capootech.com/` -> `root /opt/sites/capootech/current`（静态 HTML/CSS）
  - `https://capootech.com/images/*` -> `/opt/sites/capootech/current/images/*`
  - `https://capootech.com/api` 与 `https://capootech.com/api/*` -> 301 到 `https://grain.capootech.com$request_uri`

## 3. 代码发布（标准流程）

### 3.1 本地准备

```bash
git checkout main
git pull origin main
```

### 3.2 同步代码到服务器

```bash
git archive --format=tar -o .deploy-main.tar main
scp .deploy-main.tar capoo-hk:/opt/gain-project/.deploy-main.tar
ssh capoo-hk "cd /opt/gain-project && tar -xf .deploy-main.tar && rm -f .deploy-main.tar"
```

### 3.3 重建并启动生产容器

```bash
ssh capoo-hk "cd /opt/gain-project && docker compose -f docker-compose.prod.yml up -d --build"
```

### 3.4 发布后验证

```bash
curl -I https://grain.capootech.com
curl https://grain.capootech.com/api/health
curl https://grain.capootech.com/api/v1/info
curl -I https://capootech.com
curl -I https://www.capootech.com
curl -I https://capootech.com/api/health
```

### 3.5 主域引导页发布（仓库托管）

```bash
# 在本地仓库执行
release_id=$(date +%Y%m%d%H%M%S)
ssh capoo-hk "mkdir -p /opt/sites/capootech/releases/${release_id}"
scp -r sites/capootech/* capoo-hk:/opt/sites/capootech/releases/${release_id}/
ssh capoo-hk "ln -sfn /opt/sites/capootech/releases/${release_id} /opt/sites/capootech/current"
ssh capoo-hk "nginx -t && systemctl reload nginx"
```

主域目录规范：

- 发布目录: `/opt/sites/capootech/releases/<release_id>/`
- 当前软链: `/opt/sites/capootech/current`
- 历史备份: `/opt/capootech-landing`（只读保留，不用于现网 root）

补充接口冒烟（建议）：

```bash
# 1) 上传
curl -F "file=@test_files/test_document.docx" https://grain.capootech.com/api/v1/upload

# 2) 改写（句子单元）
curl -X POST https://grain.capootech.com/api/v1/rewrite \
  -H "Content-Type: application/json" \
  -d '{"text":"This is a sentence.","mode":"ai_detection","language":"en","unit":"sentence","option_count":2}'

# 3) 导出（需要替换成真实 doc_id 和段落 id）
curl -X POST https://grain.capootech.com/api/v1/export \
  -H "Content-Type: application/json" \
  -d '{"doc_id":"doc_xxx","modifications":{"para_000000":"REPLACED"}}'
```

## 9. 注意事项

- 生产环境不要使用 `next dev`，必须使用 `next build + next start`。
- 后端生产环境不要使用 `uvicorn --reload`。
- 预览环境与生产环境必须使用独立目录和端口，不要共用。
- `backend/.env` 属于敏感配置，不要覆盖或提交到仓库。
- 发布后建议至少观察 10-15 分钟日志，确认无持续重启和 5xx。

## 11. 主域跳转缓存排查

若浏览器访问 `https://capootech.com` 仍跳转到 `grain`，通常是旧 `301` 被浏览器缓存。按以下顺序排查：

1. 服务端基线校验（不受浏览器缓存影响）：
```bash
curl -I https://capootech.com
curl -I https://capootech.com/api/health
```
2. 浏览器无缓存验证：隐身窗口 + 强制刷新（Ctrl+F5）。
3. 清理站点数据：删除 `capootech.com` 的缓存、cookie、HSTS 条目后重试。
4. 若 `curl` 为 `200` 且浏览器仍跳转，可判定为客户端缓存问题而非服务端配置问题。
